# Лабораторная работа №3

Проект реализует вариант `C-5 — дек с сегментированным буфером` на базе собственной иерархии `Sequence`, перенесённой из `lab_2`, и дополнительную алгоритмическую задачу `A-1 — подсчёт числа инверсий` тремя способами.

## Что реализовано

- `DynamicArray`, `LinkedList`, `Sequence`, `ArraySequence`, `ListSequence`
- mutable/immutable варианты последовательностей
- `SegmentedDeque<T>` с двумя режимами хранения таблицы блоков:
  - `ArraySequence`
  - `ListSequence`
- mutable/immutable варианты целевого АТД:
  - `MutableSegmentedDeque<T>`
  - `ImmutableSegmentedDeque<T>`
- операции целевого АТД:
  - `PushFront`, `PushBack`, `PopFront`, `PopBack`
  - доступ по индексу, `Front`, `Back`
  - `Concat`
  - извлечение поддека
  - поиск подпоследовательности
  - `Map`, `Where`, `Reduce`
  - `Sorted`, `MergeSorted`
  - преобразование в `Sequence`
  - диагностика внутренней layout-структуры сегментов
- алгоритмическая часть `A-1`:
  - через `map + reduce`
  - многопроходным способом
  - за один проход с вспомогательным списком
- консольный интерфейс
- модульные тесты
- замеры производительности

## Что показывать на защите

1. Создать дек с маленьким размером сегмента, например `3` или `4`, чтобы было видно разбиение на блоки.
2. Выполнить `PushFront` и `PushBack`, затем показать `layout`.
3. Показать разницу между `mutable` и `immutable` версиями.
4. Запустить `Map`, `Where`, `Reduce`, `Sort`, `MergeSorted`.
5. На случайном наборе показать три алгоритма подсчёта инверсий и сравнить время.

## Почему это решение удобно защищать

- структура дека наглядная: элементы лежат не в одном массиве, а в наборе сегментов фиксированного размера;
- хорошо объясняется выигрыш идеи segmented buffer: уменьшается число больших перераспределений памяти;
- есть демонстрация ООП:
  - шаблоны
  - полиморфизм
  - mutable/immutable поведение
  - единый интерфейс для двух стратегий хранения блоков;
- есть отдельная алгоритмическая часть, которая напрямую работает с построенной структурой.
